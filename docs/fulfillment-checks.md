# 逐项履约核验（演示能力）

更新日期：2026-10-26（Asia/Shanghai）。此功能用于让管理员分开记录四项人工核验结论，不会访问客户账号、收集 Session/Card 资料或执行付款、停续费、删卡。人工填写“已核验”也不等于平台获得正式渠道回执。

管理员可在「商品套餐」打开“要求逐项核验”。该设置只影响新订单；订单创建时快照该标记。已有演示商品默认关闭，既有订单不改动。打开标记的订单不会由 mock worker 自动标记完成。

在「订单管理」打开“逐项核验”，依次记录 Card 付款、订阅权益生效、停止续费、移除支付方式。每步可标记“已核验”或“失败”，并填写非敏感的回执号或工单号；不得输入 Session、Cookie、密码、完整卡号或 CVV。更改前一步会撤销后续核验结论，需重新检查。所有步骤均为“已核验”后，管理员才能使用“完成”；失败、取消、退款或已完成的订单不能再修改核验记录。每次状态改变都有订单事件与管理员审计。

接口会拒绝包含 `session`、`cookie`、`password`、`passwd`、`cvv` 或“完整卡号”等凭据提示词的备注和回执引用；请使用非敏感的工单号或供应商回执号。

这项门禁只约束标记过的订单。历史订单和普通演示商品仍按原有规则处理。真实销售前，需要确定付款与履约主体、正式授权方式、可信回执、失败与退款规则，并完成支付/履约沙盒验收。

验收顺序：新建测试商品并打开逐项核验 → 使用演示余额创建订单 → 确认 mock worker 不自动完成 → 尝试提前“完成”并确认被拒绝 → 依次填写四项核验 → 确认完成可执行 → 确认订单事件、审计记录以及没有敏感凭据。
