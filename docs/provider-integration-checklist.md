# 授权履约接入清单

取得正式服务商资料后，必须逐项确认并由供应商在沙盒环境验证。没有这些资料，不得把 `FULFILLMENT_MODE=authorized` 宣称为真实充值。

## 必须提供的合同信息

- 服务商主体、授权范围、适用地区和商品清单。
- 认证方式：短期 OAuth/token、密钥轮换、权限范围、过期和撤销。
- 充值/开通请求：商品ID、客户授权引用、金额、请求幂等键、超时和限流。
- 订阅查询：当前方案、到期时间、自动续费状态，错误码和隐私字段。
- 取消续费和移除支付方式：二次确认、幂等语义、不可逆操作提示和回执。
- 回调：HTTPS 地址、签名算法、时间戳/重放窗口、事件ID、重试规则和状态顺序。
- 退款、撤销、人工介入、对账文件、服务等级和数据保留期限。

## 平台实现边界

Provider client 只能发送供应商定义的授权令牌或引用，不接受客户 Session、Cookie、密码、CVV 或完整银行卡号。卡号由合规支付服务商托管，平台只保留支付 token 和回执。

请求先写入持久 outbox，再由独立 worker 发送；每次发送使用同一个供应商幂等键。回调先验证签名、时间戳和事件ID，再按订单状态机更新；重复回调必须返回同样结果而不重复扣款或退款。对账任务按供应商账单和平台流水比较差异，差异进入人工队列。

## 上线闸门

沙盒创建/查询/取消/删除支付方式、超时、429、5xx、重复请求、乱序回调、错误签名、重放签名、退款和对账差异全部通过后，才可以申请生产配置。任何未实现的操作必须返回待人工处理，不得返回已完成。

当前仓库只实现 `authorized` 的失败闭锁占位，不发送网络请求；`mock` 仅用于演示，`manual` 用于人工履约。
