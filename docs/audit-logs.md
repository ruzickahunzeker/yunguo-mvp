# 操作日志查询与导出

后台「操作日志」使用独立页面，支持UTC日期、操作人ID、精确操作类型、目标包含筛选，分页查询、查看完整详情及CSV导出。仅管理员可以读取或导出，普通用户和代理返回403，未登录401。不会提供修改或删除日志的接口。本轮不新增表或迁移，head保持`177d4c2b1376`。

## 查询约定

```http
GET /api/admin/audit-logs?start=2026-10-01&end=2026-10-16&actor_id=1&action=products.save&target=12&page=1&page_size=20
Authorization: Bearer <管理员JWT>
```

返回原有`items/total/page/page_size`并增加`snapshot_id`（日志ID上界）。所有日志仍返回`id/actor_id/action/target/detail/created_at`，不连接用户表输出邮箱、密码哈希或登录令牌。记录包含管理员业务操作和账号安全事件，因此列名为「操作人ID」。详情按文本渲染，不执行HTML。

API不传日期时保持原有查询全部历史的兼容行为；页面默认最近30天。设置日期时必须成对，含首尾UTC自然日，最多366天；服务端使用开始日00:00≤created_at<结束日次日00:00。操作人ID必须为1–2147483647的整数；action精确匹配（最长60字符）；target不区分大小写的字面包含（最长100字符），百分号、下划线不会当作SQL通配符。分页默认20，最多100。

初次查询以当前已提交的最大ID为上界，并按ID降序。后续翻页/导出传回同一snapshot_id，排除ID更大的新增记录。重新查询重置上界，才能看到新的操作与导出审计。空库上界0，客户端显式传0仍保持空结果；超出现有最大ID的上界会收敛到当前最大ID。

这是**ID上界约束，不是数据库MVCC历史快照**：PostgreSQL并发事务可能先分配较小ID、延迟提交，后续页面仍可能看到这些后来提交的较小ID。系统不承诺跨请求的严格历史冻结，也不提供法务证据封存。日志不允许通过应用更新/删除，普通已提交记录的常规追加不会使原有页偏移。

## CSV导出

```http
GET /api/admin/audit-logs/export?start=2026-10-01&end=2026-10-16&action=products.save&snapshot_id=123
Authorization: Bearer <管理员JWT>
```

支持相同筛选，按ID降序导出完整匹配集，不受当前页码影响。单次最多10000条，超过返回413并要求缩小范围，**不会静默截断**。每账号每分钟最多5次，跨IP共享计数，超限429；生产使用Redis共享限流，故障关闭。页面超过10000条时直接禁用导出，服务端仍独立校验。

UTF-8 BOM CSV使用固定列`id,actor_id,action,target,detail,created_at,snapshot_id`，所有字段按CSV规范加引号，保留引号、逗号和多行详情。公式起始字符`= + - @`（含前置空白/BOM/控制字符）以及前置制表符、换行/回车会加英文单引号前缀，降低电子表格执行公式风险。正常中文保留。该转义会改变危险文本的CSV表现，需要精确原文时在日志详情查看；导出不是原始证据文件。文件名`audit-logs-<上界>.csv`，响应no-store，含`X-Audit-Snapshot`和`X-Export-Rows`。

导出成功在同一事务提交`audit.export`记录，含操作人、上界、行数、日期、操作人筛选及是否启用action/target筛选；不复制任意筛选文本到新审计详情。导出审计自身ID大于选取上界，不进入本次文件。审计写入/提交失败则不交付文件；超过上限/限流不记成功导出日志。每次重新下载会生成新的导出日志，不作请求幂等去重。

CSV通过带JWT的Axios请求获取，令牌不在URL。页面编辑筛选控件后必须点击查询才生效，翻页/导出沿用已经应用的条件和上界；请求失败展示错误，禁用导出，避免下载错范围。详情可能含人工填写的业务信息，拥有管理员权限的导出接收者应按敏感业务记录保管。

## 验证与后续

后端集成测试覆盖未登录/角色隔离、兼容分页与ID排序、日期首尾/最大区间、操作人/精确类型/目标字面查询、ID上界和0上界、导出审计不进入自身文件、CSV公式与多行转义、超限拒绝及账号限流。浏览器桌面/手机验证创建商品→日志筛选→详情→同目标新增操作→保持旧上界导出→重新查询看见新记录和导出审计。

尚无外部不可篡改存储、审计签名/哈希链、长期归档、合规保留策略或生产规模压力验收。持有数据库管理权限的人仍可能改动数据；不可将本功能描述为完整不可篡改审计系统。
