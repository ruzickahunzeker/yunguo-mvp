## 5. 开发启动条件

商品身份与权益、销售路径、价格和退款规则确认后，可拆分正式商品和支付状态机。取得支付/履约渠道的正式沙盒资料后，再实现对应适配器；所有回调、对账及异常用例通过后才考虑生产上架。当前 8080/8081 继续只作演示和对照，不将演示余额或 mock 完成状态作为真实交付证明。

客户 Session 属于登录凭据，不能替代正式授权渠道或可信的开通回执。即使短暂使用，也会让平台承担账号访问、支付方式操作和凭据泄露风险。当前不新增接收或代操作 Session 的接口；若暂无可用的正式授权渠道，可先完善商品规则、支付沙盒和人工核验流程，真实订阅交付继续保持关闭。

用户提出的完整操作顺序是：进入客户账号 → 用预定 Card 付款并确认订阅权益 → 停止续费 → 删除 Card 信息。它是**业务设想，不是已验收的自动履约能力**。付款、权益生效、停止续费、删除支付方式是四个独立结果；其中任一步失败，都不能在订单页声称全部完成。具体操作能否执行、取消续费后的权益有效期，以及支付方式能否删除，均需在实际授权渠道中确认。平台只应记录各步状态与非敏感回执，不记录 Session 或完整 Card 资料。

## 6. 现有实现与 Go/Plus/Pro 落地差距

- 商品目前只有名称、说明、类别、价格、库存和上下架状态，没有稳定的业务 SKU、套餐有效期、地区限制或渠道商品映射。Go、Plus 与 Pro 应分别建模，并为订单保存下单时的权益快照，避免后续改商品说明影响历史订单解释。
- 钱包购买会立即扣余额，兑换订单金额为 0 元；现有订单只记录本地支付状态和履约状态。真实收款、渠道回执和取消/退款规则需要独立状态记录与对账，不能复用演示充值作为真实收款。
- 当前演示商品由 `seed` 初始化，包含“ChatGPT Plus 月度 · 演示”，但它不代表已可销售的 Plus 权益。业务规则和正式渠道验收前，不迁移名称、不开放真实付款。
