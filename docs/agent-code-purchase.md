# 代理余额采购卡密

代理登录后在「代理中心 → 卡密库存 → 余额采购卡密」选择商品、数量和有效天数。确认窗口显示单价及总额；成功后立即下载TXT或CSV。管理员原有生成/分配方式保留，普通用户和管理员不能调用代理扣款采购接口。

服务端锁定账号、代理配置及商品，按个人专属价 → 等级价 → 默认代理价 → 零售价确定单位采购价；沿用商品采购权限和等级启用状态。必须确认当前单价，旧价格返回409；销售关闭、商品下架或需验证而未验证邮箱时拒绝新采购。

## API与事务

`POST /api/agent/codes/purchase`，JWT代理身份、`Idempotency-Key`请求头，严格整数输入：

```json
{"product_id":1,"quantity":2,"valid_days":30,"expected_unit_price":800}
```

数量1–500、有效期1–365天；金额单位为分。总额为确认单价乘数量。库存扣减、卡密哈希及所有者写入、钱包扣费和审计共用一次事务；余额不足或库存不足全部回滚。每个代理每分钟最多5次采购请求，Redis跨IP共享计数。生成卡密预留库存，客户兑换不再扣库存或代理余额。

新流水类型`code_purchase`，reference按代理与请求键HMAC去重；note只保存批次和采购合同，不保存完整卡密或请求键。无需新增表或迁移，head仍为32fb2f23c757。

## 重试与完整卡密交付

首次成功返回201及codes；同一请求键、同一合同重复请求返回同批次、replayed=true和空codes，不再扣款。同键更换商品/数量/有效期/确认单价返回409。重放只核对已有采购，不受后续价格或采购权限变化影响；当前账号仍须有效且为代理。

网络失败时页面保留原请求及请求键，重试核对原批次。原响应丢失后，完整卡密无法重新导出；应核对库存批次和账单，联系管理员核实作废和交付处理，不能为了拿到明文直接重复采购。关闭或离开页面前有保存提醒；页面不会将完整卡密写入浏览器持久存储。

卡密作废、过期和兑换失败不自动退回余额或库存。售后由管理员核实，并通过带原因的受控钱包调整记账；没有新增代理自助退款或完整卡密历史导出。

## 统计口径

代理概览单列卡密采购累计金额，账单记录每批次扣款。现有交易报表按订单统计；另有管理员[卡密采购报表](code-purchase-reports.md)汇总发卡扣费；公开兑换订单仍为0元，不重复记销售收入。卡密采购金额不是代理线下销售额或利润。管理员免费分配的卡密也计入持有库存，但不计代理采购扣款。

无真实支付、订阅开通、授信账期或多级佣金。
