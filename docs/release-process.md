# 发布与持续验收

当前仓库为私有 GitHub 仓库 `ruzickahunzeker/yunguo-mvp`。每次推送会运行 `backend` 和 `browser` 两个 CI 作业；本地发布前也应运行后端回归和 Node 22 前端构建。

当前 GitHub 账号套餐不支持私有仓库的分支保护 API，因此不能把“必须通过 CI 才能合并”设为远端强制规则。替代流程是：

1. 所有变更先在本地分支完成并运行测试；
2. 推送后等待 GitHub Actions 的 backend/browser 均成功；
3. 通过后创建版本标签；
4. 演示部署前备份数据库、执行迁移、检查 `/api/health`、容器状态和钱包对账；
5. 失败时回滚到上一个版本标签，不直接修改演示数据。

已创建演示基线标签 `v0.1.0-demo`。分支保护可在升级 GitHub Pro 或迁移到支持规则的组织仓库后启用；在此之前，标签和 CI 结果是发布记录，不代表生产门禁已经自动强制执行。
