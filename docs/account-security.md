# 账户限流、变更并发保护与审计

本轮不新增表或迁移，head仍为32fb2f23c757，共24表。

登录原有IP每5分钟10次仍生效；增加按规范化小写邮箱HMAC跨IP共享的每15分钟20次尝试限制。成功/失败/未知邮箱的尝试都计数，避免未知邮箱处理泄露账号存在性。限流键不含明文邮箱或密码；生产Redis共享计数、故障关闭；超限429并返回Retry-After。该限制是临时窗口限制，不持久停用账号；大量分布式尝试可使该账号在窗口内暂时无法登录，用户需等待窗口结束，仍需后续MFA/风控。

改密请求增加IP每5分钟10次及账号跨IP每5分钟5次共享限制，校验原密码前计数。密码错误不修改账号、不生成成功改密审计；成功后原JWT全部失效。

资料修改、改密、退出先保存鉴权时的token_version，再锁账号并重新读取active/version；若账号已停用、版本改变或记录不存在，统一401，不执行修改。这样管理员停用/改权或另一个改密/退出先提交时，旧会话不能继续用已读的账号对象写入。两个并发改密只能一个成功，后一个会话版本失效。退出在同一锁下递增版本，保留退出所有设备语义。

资料修改记录auth.profile-updated；改密记录auth.password-changed；退出记录auth.logout。审计只保存操作人ID、目标ID及固定说明，不保存原/新密码或昵称原文。审计与变更同一事务，写入失败会回滚，防止出现无审计的成功变更。

这没有增加MFA、验证码、单设备会话管理或改变JWT存放方式。服务端权限、钱包扣款和订单状态机不变。持续验收中的原8080环境先保持不动，本轮使用独立Compose项目/8081端口验收新版本，避免把部署过程混入原8小时巡检。
