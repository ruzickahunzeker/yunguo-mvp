# 卡密采购报表

管理员在「管理后台 → 卡密采购报表」按UTC日期、代理ID、商品ID筛选，查看采购批次、张数、扣款金额、每日趋势和代理/商品汇总，并导出批次CSV。代理、普通用户无权访问。

## 金额口径

只读取钱包流水kind=code_purchase：一条已提交扣款流水代表一个采购批次，数量/商品/原单价来自该批次的采购合同快照，金额来自流水实际扣款。0元采购保留批次和数量。重复请求不会重复记账，因此不增加报表批次；管理员免费生成/分配、演示充值、钱包商品订单、客户兑换均不计入本报表。

卡密使用、到期或作废不会改写原采购额，后续人工钱包调整也不冲减此金额。本报表是采购扣款汇总，不是实际收款、当日净现金流、退款净额、代理线下销售额、利润或佣金。原交易订单报表保持独立，避免将兑换重复计费。

用户改名、改角色或商品改价不会影响历史采购汇总。报表只输出代理ID和商品ID，不依赖可变邮箱/商品名称。批次信息缺失或金额不等于确认单价乘数量时返回409并给出待核对流水ID，不静默丢弃不一致记录。

## 日期和上限

默认最近30个UTC自然日，起止日包含、最多366天；无采购日期补零。先按流水时间和代理筛选，再解析采购合同做商品筛选。每次最多读取10000条采购流水，超过返回413，必须缩小日期或按代理筛选；商品筛选在解析后执行，不能突破该读取上限。

汇总和明细从同一次数据库SELECT生成，避免同次报表各部分在并发采购时不一致。屏幕与后续CSV请求之间可能新增真实采购，因此后续导出可包含新批次；不是跨请求冻结快照。页面仅导出上次成功查询的条件，未应用的表单修改不改变导出条件。

## API和CSV

- `GET /api/admin/reports/code-purchases`：参数start/end、agent_id、product_id；返回summary/daily/agents/products，不返回批次明细。
- `GET /api/admin/reports/code-purchases/export`：同参数；CSV每批次一行及TOTAL，金额单位整数分；batches/quantity/amount总计可核对。
- 导出每管理员每分钟5次，Redis跨IP共享；超限429及Retry-After。成功导出记reports.code-purchases-export审计，与响应在同一事务内提交。
- CSV只含固定字段、日期、校验过的十六进制批次、整数ID/数量/金额和筛选元数据，不含任意名称/邮箱、完整卡密、哈希、钱包请求键或查询凭证，避免电子表格公式注入来源。响应no-store。
