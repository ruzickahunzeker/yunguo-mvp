# 直属代理归属与团队业绩

管理员在「代理管理」搜索代理，使用「设置上级」填写有效代理ID，清空ID可解除归属。「名下业绩」查看该代理当前直属团队。代理登录后在「名下代理」查看自己的团队；不存在独立总代角色，有直属成员的代理在该页面承担总代查看职责。

只允许一层直属关系：一个代理只能属于一名上级；上级不能再归属其他代理，有名下代理的账号也不能再设置上级。管理员分配、调整、解除归属均记审计；界面提交expected_parent_id防止旧页面覆盖新归属。PostgreSQL用roles.agent行的NO KEY UPDATE锁串行化归属修改，避免不同端点的并发新增形成多层或环；SQLite使用既有BEGIN IMMEDIATE写事务。沿用现有agent_relations表，不新增迁移。

## 权限

- `PUT /api/admin/agents/{id}/parent`：仅管理员，提交parent_id及必填expected_parent_id（无上级时null）。重复同状态不重复写审计；旧状态不匹配409。双方须为已配置有效代理，自身/多层/循环关联拒绝。
- `GET /api/admin/agents/{id}/team`：管理员查看指定代理的直属团队。
- `GET /api/agent/team`：代理只能查看当前身份的直属团队，不接收可切换身份的parent_id。普通用户与管理员不可用此代理接口；管理员使用后台接口。
- 不提供下级订单明细、邮箱、密码/令牌、钱包余额、流水明细、完整卡密或查询凭证。总代不能修改下级账号、价格、权限或余额，也不能自行分配归属。
- 下级账号被停用仍保留其历史汇总并标明停用；改为非代理后从团队报告中排除。关系不会自动删除；重新授予代理角色后原归属会恢复，因此降级前应先解除归属。

## 统计口径

start/end为UTC自然日，默认最近30天，最多366天；可按昵称字面包含查询、分页（每页最多100）。summary覆盖筛选后的全部成员，空页保留全局总计；总计及分页行采用同一数据库语句的一致快照。搜索不匹配时返回空团队。

- order_count、gross_amount：日期范围内创建的钱包订单数和原始采购额。
- refund_amount：这些订单当前已退款的金额；按订单创建日归集。
- net_amount：gross_amount减refund_amount。
- code_purchase_amount：日期范围内code_purchase流水扣款额，卡密兑换不重复计入。
- code_count：成员当前持有的累计卡密数量（包括已使用、作废、到期），不按日期筛选。

团队按当前归属计算：管理员转移代理后，其在选定日期内的历史采购汇总随当前归属可见，不记录历史归属分成，不等同账期结算。订单和发卡两类金额单列，管理员免费分配卡密不算采购额。没有实际线下转售价、利润、佣金、递归分销或授信账期。
