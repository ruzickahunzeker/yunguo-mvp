# 交易统计报表

后台新增「统计报表」（`/admin/reports`），只有管理员可以查询和导出，普通用户与代理访问API返回403，未登录401。不新增数据库表，迁移版本保持`177d4c2b1376`。

## 统计口径

筛选使用**UTC订单创建日期**，起止日都包含。默认最近30个自然日，最多366天，可按订单来源（全部/钱包购买/卡密兑换）、商品ID筛选。没有订单的日子补零；无匹配商品返回零汇总和空商品列表。商品列表按净额降序、ID升序稳定排列，默认每页20、最多100；分页不影响总计和每日数据。

| 字段 | 定义 |
|---|---|
| orders | 匹配的全部订单，含失败、已取消、已退款和0元订单 |
| wallet_orders / code_orders | 钱包购买 / 卡密兑换的单数 |
| gross_amount | 钱包订单原金额之和，包含后来退款的原订单 |
| refund_amount | 当前支付状态REFUNDED的钱包订单金额之和 |
| net_amount | gross_amount减refund_amount，均为整数分 |
| refunded_orders | 当前支付状态REFUNDED的订单数 |
| completed/failed/queued/processing/canceled_orders | 各当前履约状态单数（与支付状态分别统计） |

例如10月1日购买1000分、10月3日失败后退款，该订单在10月1日显示成交1000、退款1000、净额0；10月3日不会凭该退款多出一笔成交。它是**按创建日期归集、按当前状态计算的订单报表**，不是当日现金流报表。退款发生时间可从退款流水核查。没有真实支付渠道收入证明、利润成本或佣金数据。

卡密代表预付权益，公开兑换订单金额0，不重复计成交额；演示充值不直接计入订单成交额，但使用演示余额购买的订单会计入，所以页面明确标注含演示资金。零元钱包订单保留订单数。

金额来自订单快照，不取商品当前售价。下架、改价不改变历史金额。商品汇总只返回ID，避免将多次改名的商品误作同一历史名称。汇总/每日/商品数据来自单次聚合SELECT的一份结果，保证响应内部一致；不同请求之间实时状态可能变化。

## API

```http
GET /api/admin/reports/sales?start=2026-10-01&end=2026-10-16&source=wallet&product_id=1&page=1&page_size=20
Authorization: Bearer <管理员JWT>
```

返回`start/end/timezone/source/product_id/summary/daily/products`；products为`items/total/page/page_size`分页。source只接受wallet/code，省略代表全部；product_id必须为正整数。非法日期、逆序或超过366天返回422。日期边界按UTC半开时间区间查询（结束日次日00:00之前）；PostgreSQL分日显式转换UTC，不受连接时区影响。

```http
GET /api/admin/reports/sales/export?start=2026-10-01&end=2026-10-16&source=wallet&product_id=1
Authorization: Bearer <管理员JWT>
```

导出完整区间的每日数据及TOTAL合计，不受页面商品分页影响。UTF-8 BOM CSV支持中文Excel；金额为整数分，不加货币符号。每行携带filter_source/filter_product_id，all代表未筛选。列名为固定英文契约，指标含义见上表；文件名包含起止日期。

CSV只输出固定标识、日期和整数，不输出用户名、邮箱、任意商品文本、完整卡密、凭证或请求键。no-store响应，浏览器通过带JWT的请求获取文件后下载，不把令牌放在URL。导出写`reports.sales-export`审计（账号、范围、来源、商品ID、天数），每账号每分钟5次，跨IP共享限制，第6次429；失败限流不写成功导出日志。导出失败审计提交会导致请求失败，不返回未记录的导出文件。

页面查询应用筛选后才更新统计，编辑但尚未查询的控件不会悄悄改变导出范围；导出使用上次已应用的筛选。因订单实时变化，导出与先前页面可能数值不同，需重新查询确认。

## 验证与限制

后端测试覆盖权限、当前状态与退款、金额整数精度、0元订单、UTC首尾与非UTC连接、来源/商品筛选、空数据补零、最长区间、分页与全局总计、CSV合计和敏感字段隔离、审计和账号限流。桌面/手机浏览器通过真实购买→人工失败→退款→页面筛选→下载CSV核对137分成交及退款。

不替代内部钱包CLI对账或未来支付渠道对账；未进行生产大数据量性能与多浏览器验收。日期范围受限，但聚合成本仍与匹配订单和商品数量有关，需根据实际数据量的执行计划安排索引或预聚合。

代理余额采购卡密记入code_purchase钱包流水；当前订单报表仅汇总订单；另有[卡密采购报表](code-purchase-reports.md)汇总发卡采购扣费。请通过代理账单和概览核查批次采购额，卡密兑换不重复记收入。
