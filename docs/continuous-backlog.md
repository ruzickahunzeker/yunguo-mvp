## 阶段 2：真实支付沙盒

依赖商户主体、支付渠道合同、沙盒账号、验签密钥和退款文档。

1. 预订单与金额快照。
2. 支付成功、失败、超时和重复回调。
3. 签名、时间戳、事件 ID 和重放防护。
4. 原路退款、拒付和退款回调。
5. 渠道账单下载、日对账和差异人工队列。
6. 支付渠道不可用时保持待支付/待人工，不伪造成功。

## 阶段 3：合法授权履约沙盒

依赖正式授权服务商合同、商品 ID、API 文档、沙盒和 Webhook 签名规范。平台不接收客户 Session、Cookie、密码、CVV 或完整卡号。

1. 独立 provider client 与 durable outbox。
2. 固定供应商幂等键和租约恢复。
3. 创建、查询、失败、取消、重试、超时和部分成功。
4. 取消续费与移除支付方式的独立回执。
5. Webhook 签名、乱序、重放和重复事件。
6. 供应商账单与平台订单逐笔对账。
7. 无法自动完成的操作进入人工队列，不能返回已完成。

## 阶段 4：生产门禁与运营

- HTTPS、PostgreSQL、Redis、密钥管理、MFA 和最小权限。
- 异地加密备份、恢复演练、容量告警和回滚版本。
- 外部可用性、错误率、队列积压、worker 心跳和对账差异监控。
- 客服工单、退款审批、证据附件和处理时限。
- 灰度发布、观察窗口、回滚阈值和值班安排。
- 服务条款、隐私政策、退款政策、商品页风险提示。

## 自动执行规则

1. 优先执行阶段 0；每次修改后先静态检查，再运行定向测试，再提交。
2. 网络恢复后推送本地提交并查询 CI；不强推远端、不覆盖他人提交。
3. 缺少阶段 1–3 的外部资料时，只完善模拟适配器、人工队列、文档和测试，不发送真实请求。
4. 任何“已完成”必须关联证据；演示余额、mock 队列和人工核验不等同于真实订阅交付。
